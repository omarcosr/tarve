# Changelog

All notable changes to `@tarve/core`, `@tarve/react-icons` and `@tarve/headless` are documented here. Versions follow [Semantic Versioning](https://semver.org/); before 1.0, minor versions may contain breaking changes.

## Unreleased

### Added
- Command-line automation of any finished app, without changing its code: `app.exe --tarve-script="click:Tasks;type:Hi;key:Enter" --tarve-snapshot=shot.png --tarve-inspect=tree.json` (or `TARVE_SCRIPT`/`TARVE_SNAPSHOT`/`TARVE_INSPECT`) clicks by visible text, types, presses keys, waits and captures once the first frame is drawn, then closes (`--tarve-keep` leaves it open); a failed step exits with code 1.
- Tooling: `bun run bench:compare` appends each run to `work/bench-history.jsonl` (`LABEL=`, `HISTORY=`) and shows Δ against the previous and the best run (±5% is noise); the benchmark app gains `boxes`, `text` and `list` (100,000-row VirtualList) scenes. `bun run test:renderer-parity` compares the CPU and GPU renderers pixel by pixel, and `bun run check:lines` keeps new source files under 600 lines while legacy ones may only shrink (`scripts/lines-baseline.json`). Both run in `bun run verify`.
- Native ABI 6: `tarve_allow_foreground(pid)`, so a second launch hands the foreground to the first instance from Bun, Node.js and txiki.js alike (it called `bun:ffi` directly before, a no-op under Node.js). `WindowPosition` coordinates take `physical: true` (screen px); remembered windows save physical positions, so a window left on a monitor of another scale reopens where it was. The instance socket on macOS/Linux lives in `$XDG_RUNTIME_DIR` or a 0700 per-user directory (any local user could hand the app arguments through the shared temporary directory), launch arguments are `argv.slice(2)` in compiled executables too (Bun puts the embedded entry at `argv[1]`), `registerUrlScheme` quotes commands for `CommandLineToArgvW` and desktop-entry `Exec` rules, and every window keeps its own DPI-frozen logical size while moved across monitors (only the first did).
- Several windows per app: `app.openWindow(view, { id? })` opens another window from its own `<Window>` view and returns its own `AppHandle` (`update`, `close`, `closed`, `ready`, `onEvent`, `inspect`, `layout`, dialogs…), so each window renders, diffs and handles events on its own while they share the app's state. Natively all windows run on one event loop (`Host` in `runtime.rs`): each has its own tree, renderer and accessibility tree, events carry the window id (`"window"`) and commands for a window travel as `toWindow`; the earliest wake-up of any window drives the loop. The tray, notifications, media session, desktop widget, `alwaysOnBottom` and `skipTaskbar` stay with the first window, closing a window closes only it, and closing the first one closes them all. New `examples/windows` and `bun run smoke:windows`.
- Menu bars: `app.menuBar(items | null, { native? })` puts a menu bar at the top of the window (after a `TitleBar`), drawn in the theme and the same on every system, framed or frameless; `<AppMenuBar items>` places one anywhere (inside a `TitleBar`). Top-level items with `items` are its menus, with separators, checkmarks, disabled items and submenus; menus open on click and follow the pointer while one is open, arrows move along the bar and through a menu (Left/Right go to the next menu, into and out of a submenu), Enter/Space choose and Escape closes; F10 focuses the bar and Alt+<access key> (`&File`) opens a menu at its first item; `accelerator` (`Ctrl+S`) is shown next to the label and registered as a window hotkey. A choice runs the item's `onSelect` and reaches `onEvent` as `{ type: "menu", id }`. `{ native: true }` uses the Win32 menu instead (framed windows only; other systems report an error). Natively, a navigation group with an orientation now roves along it only (a horizontal bar leaves Up/Down to its buttons), a popup trigger (`expanded` button) reports Up/Down and an item of a vertical menu Left/Right as `key` events. `bun run smoke:menu-bar` checks both bars with the pointer and the keyboard.
- Editing chords stay with a focused text field: Ctrl/Cmd+A, C, V, X, Z, Y and word moves no longer reach app hotkeys or menu accelerators while an input or textarea has focus (Ctrl+S still does).
- A window `openWindow` asked for and native refused reports the error to that window and fails its `ready`, instead of leaving it waiting.
- A transparent window drawn by the GPU on Windows is created without a GDI redirection surface (`WS_EX_NOREDIRECTIONBITMAP`): nothing opaque under the composition tree to paint over at creation and on every resize. If only the CPU renderer can open, the window is made again with one. On Linux (X11) the file drop target under the pointer is read from the X server during a system file drag, as on Windows.
- Remembered windows: `createApp(view, { rememberWindow: true | "key" })` (and `openWindow`'s option, keyed by the window id) saves the window's restored size, position and maximized state per user in `<config dir>/<app>/window-state.json` (`appConfigDirectory()`: %APPDATA%, ~/Library/Application Support or $XDG_CONFIG_HOME) and reopens it that way; minimum sizes still hold, and a saved position off every monitor (one unplugged since) reopens centred. Natively `WindowOptions.maximized` opens a window maximized over its restored bounds and `reportWindowState` reports them as `windowState` events. `bun run smoke:window-state` moves, resizes, maximizes and reopens a real window.
- One instance per app and links that open it: `requestSingleInstance({ id?, schemes? })` (before `createApp`) makes the first launch `primary` and hands every later launch's arguments, working directory and links (`urls`) to it over a per-user named pipe (Windows) or Unix socket, then reports `primary: false` so the later process can exit; the first hears them through `onSecondInstance`. On Windows the later launch lets the first take the foreground (`AllowSetForegroundWindow`), and the new `app.activate()` (window action `activate`) shows, restores and focuses the window. `registerUrlScheme(scheme, { name?, command? })` / `unregisterUrlScheme` make `scheme://…` links open the app for the current user (Windows: HKCU\\Software\\Classes; Linux: a desktop entry made the `x-scheme-handler` default with `xdg-mime`); a link then arrives as `launch.urls` or through `onSecondInstance`. macOS delivers links as Apple events from the bundle's Info.plist, not handled yet: `registerUrlScheme` throws there. `bun run smoke:single-instance` checks the hand-over, the foreground and a link opened through the Windows shell.
- Files dragged in from the system (Explorer, Finder, a file manager): `onFileDrop`, `onFileDragEnter` and `onFileDragLeave` on any view (or `<div>`, or the `Window`) make it a file drop target (`fileDropTarget`); the innermost enabled, visible target under the pointer gets `{ paths, x, y }`, and `app.onEvent` sees a `fileDrop` without `id` for files dropped outside every target. The system reports no pointer moves during the drag, so on Windows the target under the pointer is read from the OS cursor every 50 ms while files hover; on macOS and Linux (X11) the drop goes to the target under the last known pointer. `bun run smoke:file-drop` drives a real OLE drag of two files across two zones.
- See-through windows: `<Window backdrop="transparent" | "blur" | "mica" | "acrylic">` (`WindowOptions.backdrop`). The window background defaults to transparent, and every translucent pixel (the background, any colour with alpha) shows what is behind the window: as it is (`transparent`), blurred by the system (`blur`), or through the Windows 11 Mica and Acrylic materials (`blur` on other systems; the accent blur on Windows 10). Windows: the D3D11 renderer presents through DirectComposition with premultiplied alpha, the CPU renderer writes premultiplied pixels; Vello/DX12 stays opaque. macOS and Linux: per-pixel alpha through wgpu when the surface offers a composited alpha mode (and softbuffer on X11's 32-bit visuals), the blur through winit (macOS, KDE). On Windows `blur` is the accent blur of the windows behind, which stays while the window is inactive; Mica (which tints the wallpaper, not the windows behind) and Acrylic turn solid while it is inactive, as the system's own windows do, and all three are solid while Windows "Transparency effects" is off, reported by `app.inspect().transparencyEffects` (`windowAlpha` says whether the window composes alpha at all), and `app.onEvent` receives a `transparencyEffects` event when the setting changes. A material window opens without DWM's open animation, during which the system draws no material (the desktop showed through for ~250 ms); later minimize/restore animations are kept, and an `acrylic` window stays cloaked through the ~250 ms fade-in of the material, so it appears with its final look. The material is light or dark after the window background's lightness (the app theme), not the system theme. `bun run smoke:translucent` puts striped windows behind each backdrop and checks the screen pixels (Windows; `TARVE_SMOKE_TOGGLE_TRANSPARENCY=1` also switches the setting to check the event). New `examples/translucent` (`bun examples/translucent/translucent.tsx mica`).

### Fixed
- `TextArea` with Windows line breaks: `\r\n` and `\r` in `value` (and in pasted text) become one `\n`, as in an HTML textarea, so a file opened from disk no longer shows an empty line after each line where the caret could stop between `\r` and `\n`; `onChange` reports `\n`. Tabs are drawn `style.tabSize` spaces wide (new, default 8) instead of as a missing glyph, and pasted tabs are kept.
- A wheel notch over a `TextArea` eases like one over a scroll view, and the pointer over a scrollbar (or dragging one) is the arrow, as in a browser, whatever the content under it.
- New `examples/notes`: a small text editor with file drops, a single instance and a `tarvenotes://` link, a remembered window, the menu bar and a theme toggle in the title bar; it reads UTF-8, UTF-16 and legacy (Windows-1252) files and saves them back in their encoding and line endings.

## 0.6.0 — 2026-10-15

### Added
- Signed auto-updates: `tarve keygen` creates an Ed25519 key pair, `tarve release` copies built executables and writes a signed `latest.json` (size and SHA-256 per platform), and `checkForUpdate`, `downloadUpdate`, `installUpdate` and `canInstallUpdate` let a built app update and restart itself. Manifests, URLs (HTTPS only), versions (newer only), app names, sizes, hashes and executable formats are validated on both sides. `tarve release --sign "<command> {file}"` (or `TARVE_SIGN_COMMAND`) Authenticode-signs Windows executables before hashing. `tarve build` now bakes the app version into the executable. See `/docs/updates`.
- Tailwind utility classes on native views, with no CSS and no DOM: `class` (or `className`) on any element compiles to its native `style` at the JSX call site, and `tw("…")` returns the same `Style` for component `style` props (falsy arguments are skipped, as with `clsx`; an inline `style` wins). Covered: layout (`flex`, `grid`, `items-*`, `justify-*` including `around`/`evenly`, `gap-*`, `gap-x-*`/`gap-y-*`, `inset-*`, `z-*`), spacing and sizing (fractions, `full`, arbitrary `[12px]`/`[50%]`), the full colour palette with `/opacity` modifiers, theme tokens (`bg-primary`, `text-muted-foreground`, `border-border`, also with `/opacity`), typography (`text-sm/6`, `font-*`, `leading-*`, `tracking-*`, `truncate`, `line-clamp-*`, decorations), borders and radii (`rounded-t-lg`, `rounded-tl-*`…), `shadow-*`, `ring-*`, `outline-*`, `opacity-*`, `cursor-*`, `select-*`, `overflow-*`, transforms (`scale-*`, `translate-*`), transitions (`transition`, `duration-*`, `delay-*`, `ease-*`), gradients (`bg-gradient-to-r from-… via-… to-…`) and the `hover:`, `focus:`, `focus-visible:`, `active:`, `disabled:` and `dark:` variants. Also `mx-auto` and friends (auto margins, new in the protocol: `Margins` sides take `"auto"` and percentages), `start-*`/`end-*`, the container scale on widths (`w-xs`, `min-w-sm`), `space-x/y-*` (as a flex gap), `object-*`, `bg-radial`/`bg-conic`/`bg-linear-<angle>` with `from-10%`-style stop positions, coloured shadows (`shadow-red-500/50`), `inset-shadow-*`, `text-shadow-*`, `backdrop-blur-*`/`backdrop-saturate-*` (as the glass material), `animate-spin`, `sr-only`, `outline`, `aspect-3/2`. Breakpoints and `group-hover:` have no native counterpart and are dropped. New `examples/tailwind`: a live playground that shows the style a class list compiles to, a palette with a shade slider, per-corner radius controls, tabs, a gap slider, gradients and a runtime theme switch.
- A parity suite (`packages/core/src/tailwind-parity.test.tsx`) compiles ~230 utility classes, variants, arbitrary values, gradient and coloured-shadow combinations with the Tailwind CSS 4 compiler itself (`@tailwindcss/node`) and compares every declaration with what `tw()` produces, after resolving its theme variables, `calc()`, `oklch()` and `color-mix()`; the few intentional differences (`inline-flex`, `static`, viewport units, generic font families, `space-*` as a flex gap, `ease-*`/`delay-*` without a duration, Tailwind's transition property list) are listed and asserted there. The colour palette is Tailwind 4's OKLCH palette mapped into sRGB as browsers paint it, generated into `packages/core/src/tailwind-palette.ts` by `bun scripts/tailwind-palette.ts` (`bun run check` fails when it is stale).
- `Style.dark`: overrides applied when the window theme is dark (its background luminance below 0.5), folded by the reconciler so the native tree never sees the key; also inside inline spans.
- `Style.radius` takes an object, `{ topLeft, topRight, bottomRight, bottomLeft }`, for per-corner radii. The box, its clip, the solid border and the inner padding-box radii (shrunk by the adjacent border widths, as CSS does) follow each corner; `radius` still transitions, corner by corner. Shadows, glass and outlines use the largest corner for now.
- `Style.rowGap`/`columnGap` (CSS `row-gap`/`column-gap`), each falling back to `gap`; `justify` accepts `"around"` and `"evenly"`.
- Layout and paint keys the CSS vocabulary needed: `alignSelf`, `alignContent`, `justifyItems`, `justifySelf` (Taffy had them; the protocol now exposes them), `align: "baseline"`, `justify: "stretch"`, `textAlign: "justify"`, `pointerEvents: "none"` (the pointer falls through the box and its children) and `transform.rotate`/`skewX`/`skewY` in degrees about `originX`/`originY` (fractions of the box), all animating with `transition`.
- Style variants beyond the pointer states: `group: true` marks a box and `groupHover` applies to its descendants while it is hovered (Tailwind's `group-hover:`); `focusWithin` applies while the box or a descendant has focus; `first`/`last`/`odd`/`even` apply by position among the parent's element children; `sm`/`md`/`lg`/`xl`/`2xl` apply when the window is at least 640/768/1024/1280/1536 px wide, and the app re-renders when the width crosses a breakpoint (the root reports its size only while some style uses one). The position and width variants are folded by the reconciler, side by side (`first:pt-0` over `p-2` keeps the other three sides), so the native tree never sees them. `tw()` emits all of them: `group-hover:`, `focus-within:`, `first:`, `md:hover:`, `dark:md:`…
- `Icon` names `play`, `pause`, `skip-back` and `skip-forward`, so a transport needs no stand-in glyphs. `over(top, bottom)` composites one hex colour over another (source-over), the operation `Glass` applies to its tint.
- Glass that flows: `<Glass merge="…">` names a surface, and every glass box of one frame with the same key is drawn as one — where two come within `blend` px of each other (default 32) their shapes bridge with a smooth union, like drops of liquid, and a box fading out (`opacity`) shrinks away out of the surface. `GlassMaterial.merge`/`blend` on `style.glass` for other nodes; the D3D11 renderer fuses up to 8 shapes per surface (the first box's tint, clip and material; later ones paint where the first does). New `examples/liquid`: a weather card and a big lens over a vivid wallpaper, a dock the drops fall into and part from, and a drop that follows the pointer. The `smoke:glass` script checks that merged drops bridge their gap.
- Liquid Glass, as in iOS 26: `<Glass>` is a container whose backdrop shows through blurred and bent at its rounded edge (a lens, with a trace of chromatic aberration), saturated, under a light veil, with a bright rim on top. `variant` (`regular`, `clear`, `tinted`), `appearance` (`light`, `dark`), `tint`, `radius`, `material` overrides (`blur`, `saturate`, `refraction`, `highlight`, `magnify`) and `shadow`. The glass is a thick slab with a quarter-round edge: the flat part enlarges the backdrop slightly, the edge bends it outward (what lies past the edge is pulled into the rim, with a trace of dispersion) and reflects (a Fresnel glow, a bright edge line, a sheen top-left); the blur is light, the lens is what reads as glass. The material is the new `style.glass` (`GlassMaterial`) on any node, with `background` as its tint; the D3D11 renderer paints it (the backdrop under the box is copied, blurred in two passes and sampled through the edge's distance field; with `msaa` on, tint only), wgpu and the CPU renderer paint the tint, so a glass UI degrades to a translucent one. New `examples/glass`: a music screen with a glass tab bar, floating toolbar, search that morphs out of a button, now-playing card with a pointer-following sheen and a settings sheet; `bun run smoke:glass` checks the blur.
- `TitleBar` takes `buttonStyle`, merged into each window control (minimize, maximize, close): round 36 px controls inside a glass capsule, as in the glass example, without giving up the standard `showMinimize`/`showMaximize`/`showClose`.
- `<TitleBar glass>` (or `glass="clear" | "tinted"`, with `appearance="light" | "dark"`) is the ordinary title bar made of Liquid Glass: veil, material, rim, round controls and the appearance's ink, while `title`, `children`, `showMinimize`/`showMaximize`/`showClose` and `buttonStyle` work as before. Lay it over content for the backdrop to show. `glassSurface(variant, appearance, options)` returns the style `Glass` uses, for any node.
- `TrayOptions`, `TrayHandle`, `TrayMenuItem`, `NotifyOptions` and `SystemMediaSession` are exported from `@tarve/core`; they were the types of `app.tray()`, `app.notify()` and `app.systemMedia()` but could not be named.
- `onScroll` (Scroll, ScrollArea, VirtualList, DataGrid, MessageScroller) gets a third argument, `{ source }`: `"user"` for the wheel, scrollbar, keyboard and assistive technology, `"program"` for `scrollToItem` and every step of a smooth one, `"layout"` when rows around the anchor change height. `onScrollPosition` carries the same `source`. A view that follows something (lyrics, a log, a "fly to" animation) can now step aside when the user scrolls, without guessing from timing. Runtimes that predate it report `"user"`.
- `Window`'s `level` can change while the app runs (a `windowLevel` command follows the re-render), and `"alwaysOnBottom"` now holds on Windows: the system placed the window at the bottom only once, so showing, clicking or dragging it brought it forward. A desktop widget takes `level` too, to switch "always behind" off.
- `Window` desktop widgets: `desktopWidget={{ columns, rows }}` (Windows) makes the window a widget on the desktop icon grid, like a home-screen widget. It is sized to whole icon cells, sits below every window, off the taskbar and Alt+Tab, and when dragged (by a `dragRegion`) it drops into the nearest cells free of icons, never over one; icons that later land under it (a file saved to the desktop, an icon dragged onto it) are moved to the nearest free cell. `position` picks where it first looks for room. The parts are also separate options: `level` (`"normal"`, `"alwaysOnTop"`, `"alwaysOnBottom"`), `skipTaskbar` (Windows: no taskbar button and no Alt+Tab entry) and `frameless` (no native frame without a `TitleBar`). New `examples/widget`: a 3 × 2 clock with CPU and memory. On Linux (X11, or XWayland on a Wayland session) a widget, `skipTaskbar` and `level` set the EWMH window states (`_NET_WM_STATE_BELOW`/`ABOVE`, `SKIP_TASKBAR`, `SKIP_PAGER`, `STICKY` for widgets), and a widget takes cells of a typical icon (80 × 100); there is no desktop icon grid to follow there.

### Fixed
- `<div onClick>` never fired: the handler was registered but the div compiled to a plain `view`, and only buttons and pressables receive native clicks. A div with `onClick` is now a `pressable`, out of the tab order unless `focusable` says otherwise, as in HTML.
- Contiguous text children of a box (`Mark {count} as read`) are one anonymous text node, as in CSS; each JSX expression used to become its own text box.
- A border with different widths per side (`borderWidth: { top: 1, right: 1, bottom: 0, left: 1 }`) on a rounded box lost its corner arcs: the sides were painted as straight rectangles clipped to the rounded shape. It is now the ring between the border box and the padding box, and the D3D11 renderer paints that ring from its distance fields (per-corner radii, antialiased on both edges) instead of the feathered path, which left a hard, jagged inner edge.
- `Glass` `tint` is laid over the variant's veil instead of replacing it: a tinted `regular` box stays frosted and legible, a tinted `clear` one shows the tint nearly alone, and `tinted` reads as its name says. A gradient tint still passes through as is.
- `<TitleBar glass>` with a `radius` in `style` is a floating capsule: full rim, drop shadow and clipped corners; without one it stays an edge-to-edge bar with a hairline at the bottom. The glass example built its controls capsule by hand from `glassChrome` and copied veil colours; it now uses the prop.
- `GlassProps.merge` documents what the renderer does: the first box of a key in tree order paints the surface (tint, material, `blend`), later ones add only their shape; `StateStyle.lineHeight` documents that it is a multiple of the font size, not px (the liquid example passed 64 and the degrees vanished).
- `app.openFileDialog`/`openFilesDialog`/`openFolderDialog`/`saveFileDialog` rejected with `Native request timed out: fileDialog` when the dialog stayed open for more than 10 s: the request meant to wait forever fell back to the default timeout. A dialog now waits for the user.
- Uncontrolled state (`<input type="checkbox">` without `checked`, `<details>`, an open `<Select>`, a hovered `Tooltip`, `<audio>` playback) belongs to the app that rendered it: `app.remount()` and a second `createApp` in the same process (tests) start clean instead of inheriting it.
- `dragRegion` on a plain `View`/`Column` now moves the window from anywhere on it, its plain text included; it only worked on `TitleBar`, which also blocks pointer events. Controls inside still get their own presses.
- An update sent right as the window closed (a timer ticking while the user clicks ✕) reported `Tried to wake up a closed EventLoop`: commands that reach a closed window are now dropped, as `closed` is already on its way.
- `skipTaskbar` on Windows stays in effect after the window is hidden, shown or changes `level`: winit rewrote the extended window style on each of those and the window came back in Alt+Tab.
- A `Window` smaller than 780×580 without `minWidth`/`minHeight` opened at 780×580: the default minimum now never exceeds the requested size. Double-clicking a drag region no longer maximizes a non-resizable window.
- A hotkey made of a typing key (`Space`, a letter, `Enter`, an arrow…, alone or with Shift) no longer fires while a text field has focus: typing a space in a search box also toggled playback in the player and YouTube Music examples. Chords (`Ctrl+K`), F-keys and `Escape` still fire.
- `app.focus` and `app.scrollToItem` called right after `app.update()` (or a state change in an event handler) reach the nodes that render adds: they used to go out before the queued render and miss a field or list it was about to create.
- `app.scrollToItem` on a list that is not mounted (another page, a hidden panel) does nothing, like `scrollIntoView` on a detached element, instead of reporting an error. A mounted node that is not a variable `VirtualList` still errors.
- `<audio src="https://…">` from googlevideo (YouTube) failed on many songs: the CDN answers 403 to a second request to a file while one is in flight, and to a range behind what it already served, and the stream used four parallel connections plus jumps for seeks. A remote file now downloads in one forward pass (4 MB ranges, one connection; a seek more than 8 MB ahead, as in a long podcast, starts a pass there), retrying 403, 429, 5xx and network errors with backoff (not 404). A 40-song soak went from 32 errors to none, in a third of the time; first sound ~0.6 s.
- `<audio>` follows the output device: when it goes away (unplugged, sleep, a driver restart) or the default output changes, a new output stream plays on from the same sample. Tracks are mixed (in the first device's own format, so samples are converted once) into one mix that outlives output streams, so nothing is reopened, reloaded or sought (a switch used to restart the song, and failing to seek could skip it).
- `<audio>` never blocks the window on the audio thread: rodio's `try_seek` and `clear` wait for the audio thread to acknowledge, so a stalled network read or a lost device froze the whole app on the next seek or song change. Seeks now run on a helper thread (`seeked` fires once done) and a replay swaps in a new player.
- A remote `<audio>` whose network stalls for 30 s reports an error (the page can reload it) instead of ending as if the track were over.

### Performance
- Each update no longer copies every native node into the shadow tree the reconciler diffs against; nodes are shared with the compiled tree and copied only when native edited them (typed text, a dragged slider). Nodes without handlers no longer allocate a 32-slot handler record. On a 2 000-row list (6 000 nodes) one update went from ~23 ms to ~19 ms of TypeScript time and the retained heap from 12.5 MB to 7.2 MB; at 30 000 nodes, 140 ms → 112 ms and 54 MB → 26 MB (`bun run bench:reconcile`). Rendering a list through `memo` stays the real win: 2.9 ms → 2.0 ms on the same tree.
- A window hidden with `app.hide()` (close to tray) drops its GPU device, swap chain and textures, stops animation ticks and layout, and trims its working set; `app.show()` builds them again and paints before the window appears. Measured on Windows with an animated window: GPU memory 29 MB → 0, CPU 3–10% → 0, threads 48 → 25, working set 39 → 20 MB; showing again takes ~80–130 ms. Minimized windows also stop animation ticks. `capture()` of a hidden window still works: it builds a renderer for that frame and gives it back.

## 0.5.0 — 2026-10-12

### Performance
- D3D11 draws circles, rounded rectangles with one radius and round SVG dots (zero-length round-capped segments, as dot-matrix charts use) as one quad each from a distance field, instead of flattening, tessellating and feathering an outline. On the Pulse example (eight dot charts refreshed every second) the app process went from ~3.2% to ~1.9% of a core and from ~120 MB to ~77 MB of working set.
- `@tarve/react-icons` adapters remember their result per icon component and props (`memoizeAdapter`), so an icon on screen runs its React component and serializes its SVG once, not on every update.

### Added
- App icon and metadata from one place: a `"tarve"` field in `package.json` (`name`, `description`, `publisher`, `copyright`, `icon`, `appId`, per-entry overrides under `apps`) or `tarve build --icon/--publisher/--copyright/--description/--app-id`. `tarve build` writes them into the executable (Bun and Node builds alike: multi-size `.ico`, version info, no Node.js branding) and writes a `.desktop` file with the icon on Linux. `createApp({ icon })` sets the window and taskbar icon (PNG or ICO, Windows and Linux), and `app.tray()` without its own `icon` shows it too; `tarve run`/`dev` and built apps pick the icon, name and app id up from the metadata, so media controls and notifications are named without an explicit `appIdentity`.
- `<Image src="https://…">` (and `<img>`): the native side fetches and decodes a URL on worker threads the first time the image is painted, so off-screen images are not downloaded, then lays it out with its decoded size. Up to six downloads run at once, newest first; a failed image is tried again when it is shown again; a remote SVG never reads local files through `<image href>`; responses with `Cache-Control: max-age` go to a disk cache. `@tarve/headless` fetches them with `fetch()` and `settle()` waits for them. Apps no longer need `loadImageSource` plus their own visibility tracking; the YouTube Music example dropped its artwork loader and every scroll listener it kept for it.
- `app.scrollToItem(id, index, offset, { smooth: true })` eases a variable VirtualList to the item on the native motion clock (300–900 ms by distance) and reports each step through `onScroll`; wheeling cancels it. The performance example's 16 ms `setInterval` scroll animation is gone.
- `inspect().fps`: frames presented in the last second, so a frame-rate meter no longer differences frame counters itself.
- `<Tooltip>` without `open` is uncontrolled: it shows while its trigger is hovered, one tooltip at a time, so apps no longer track which tip is open. `open` + `onOpenChange` still control it.

### Changed
- Windows (D3D11): 8x MSAA renders through a fixed 256px tile instead of window-sized targets, and each tile is hashed so an unchanged one is reused from the last frame. Linear-gradient bands are cut to the shape's box instead of covering ~7× its area, and draws inside a clip only mark the clip's tiles dirty; the tile hash is computed once per command per frame.
